# Теоретическая оценка сложности

Обозначения: N = H·W — число пикселей, L = 256 — число уровней яркости,
α(N) — обратная функция Аккермана (α ≤ 4 для любых практических N).
Все оценки относятся к реализациям из `src/weeddet/`.

| Шаг | Время | Память | Модуль |
|---|---|---|---|
| ExG | Θ(N) | O(N) | `exg.py` |
| Нормировка в uint8 | Θ(N) | O(N) | `exg.py` |
| Гистограмма | Θ(N) | O(L) | `otsu.py` |
| Порог Оцу по гистограмме | Θ(L) | O(1) | `otsu.py` |
| Бинаризация | Θ(N) | O(N) | `otsu.py` |
| Компоненты через DSU | O(N·α(N)) | O(N) | `components.py`, `dsu.py` |
| Компоненты через BFS (эталон) | Θ(N) | O(N) | `components.py` |

## ExG

Для каждого пикселя выполняется константное число операций (сумма каналов,
три деления, 2g − r − b). Никаких зависимостей между пикселями нет, поэтому
время Θ(N) в лучшем, среднем и худшем случае. Результат хранится в массиве
из N чисел: память O(N).

## Гистограмма и порог Оцу

Гистограмма: один проход по N пикселям, в каждом — одно увеличение счётчика:
Θ(N). Хранится L счётчиков: O(L).

Порог Оцу: для порога t межклассовая дисперсия σ²(t) = w₀·w₁·(m₀ − m₁)².
Если считать w₀, m₀ для каждого t заново, получится O(L²). Вместо этого
w₀ и сумма уровней первого класса накапливаются при переходе от t к t+1 за
O(1), а w₁ и m₁ получаются вычитанием из общих сумм. Поэтому поиск порога
стоит Θ(L) = Θ(256), то есть константу, не зависящую от размера изображения.
Итого шаг «ExG → гистограмма → Оцу» определяется гистограммой: Θ(N).

## DSU

Каждый элемент — пиксель (номер r·W + c), два списка `parent` и `rank` по N
элементов: память O(N).

| Оптимизации | Операция find/union | m операций |
|---|---|---|
| Нет | O(N) в худшем случае (цепочка) | O(m·N) |
| Только сжатие путей | O(log N) амортизированно | O(m·log N) |
| Только объединение по рангу | O(log N) в худшем случае | O(m·log N) |
| Сжатие путей + ранги | O(α(N)) амортизированно | O(m·α(N)) |

Обоснования:
- **Ранги.** Дерево ранга k содержит не менее 2^k вершин, поэтому ранг, а значит
  и глубина, не превышает log₂N. Это проверяет тест `test_rank_keeps_trees_shallow`.
- **Сжатие путей.** После `find` все вершины пути указывают прямо на корень,
  последующие запросы по ним занимают O(1). Тест `test_path_compression_flattens_chain`.
- **Вместе** (Тарьян, 1975) — амортизированная оценка с обратной функцией Аккермана.
  Доказательство в курсовой не приводится, достаточно ссылки.

## Компоненты связности через DSU

Первый проход: для каждого пикселя маски до 2 (4-связность) или до 4
(8-связность) операций union с уже просмотренными соседями. Число union не
более c·N, где c ≤ 4 — константа. Второй проход: по одному find на пиксель
маски и одно обращение к таблице меток. Всего O(N) операций над DSU, то есть
**O(N·α(N))** времени и **O(N)** памяти (parent, rank, таблица меток, массив
меток). На практике почти линейно.

Лучший случай (пустая маска): Θ(N) на просмотр пикселей, без операций DSU.
Худший случай по DSU достигается при неблагоприятном порядке объединений,
но при обеих оптимизациях остаётся O(N·α(N)).

Эталон BFS: каждый пиксель маски попадает в очередь один раз и просматривает
константное число соседей: Θ(N) времени, O(N) памяти. Это асимптотически не
хуже DSU.

## Что нужно сопоставить с экспериментом

- Время ExG, гистограммы и DSU растёт линейно по N (эксперимент по размеру изображения).
- Вклад оптимизаций DSU: четыре варианта (без / сжатие / ранги / оба) на одних и тех же масках.
- Оговорка для отчёта: в чистом Python константы велики, а на масках CWFID разница между
  вариантами DSU и BFS может быть малой. Измеренное время нужно честно сравнить с теорией,
  а не подгонять под неё.
